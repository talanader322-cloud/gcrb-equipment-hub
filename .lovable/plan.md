# خطة معتمدة — نظام كاتلوجات معدات كوماتسو (GCRB)

## 0) نتيجة فحص المستودع وقاعدة البيانات (متحقق منه فعليًا)

- التطبيق: React 19 + TypeScript + TanStack Start + Tailwind v4، عربي RTL / إنجليزي، خلفية Lovable Cloud (Postgres) بـ 35 جدولًا و14 ترحيلًا مطبّقًا، RLS + أدوار، تخزين خاص بروابط موقّعة، طبقة عمل دون إنترنت (Cache Storage + IndexedDB).
- تم فعليًا: الدخول باسم مستخدم/كلمة مرور وإدارة المستخدمين، مخطط بيانات كامل، 20 شاشة، بحث محلي بالتطبيع (D155-1/D1551) والرقم التسلسلي، رفع مانيوالات بتحقق بايتات سحرية وSHA-256 ومعاملة ذرّية، وخط Komatsu العام (فهرس ~7,891 كتابًا + استيراد مخططات).
- بيانات القاعدة اليوم: 12 مصنّعًا، 19 نوع معدة، 4 موديلات، 5 كاتلوجات، 441 مخططًا، 10,539 صفًا في `catalog_scheme_parts`، و`catalog_files` = 0 و`machine_assets` = 0.
- **أهم فجوة**: 10,539 رقم قطعة موجودة في القاعدة لكن البحث يستعلم جدول `parts` (4 صفوف) ولا يلمس `catalog_scheme_parts` — أي أن الهدف الأساسي (إدخال رقم قطعة ← معرفة المعدة والقسم والرسم) غير مُفعّل رغم توفر البيانات.
- مصادر الإنترنت: TehCat/777parts/AVRORA تستخدم `connector_key = link_template` غير المسجّل في registry، فهي روابط خارجية فقط لا بحث حقيقي.

## 1) نتيجة فحص رابط ميجا (مهم جدًا)

المجلد يحتوي فعليًا على: `KOMATSU LINKONE CSS-NET EPC USA 2022.05` = برنامج ويندوز (`CSS 5.11 SETUP.rar` ‏35MB) + قاعدة بيانات مضغوطة في 4 أجزاء RAR بحجم إجمالي **≈13.3 جيجابايت** (part1‑part4).

المعنى العملي:

- ليست ملفات PDF جاهزة، بل قاعدة EPC مغلقة (LinkOne/CSS) تعمل على ويندوز فقط.
- لا يمكن للتطبيق «البحث في ميجا» وقت التشغيل: كل استعلام يستلزم تحميل 13 جيجابايت وفك ضغط وقراءة صيغة مغلقة — مستحيل داخل بيئة الخادم أو المتصفح.
- استخراج قاعدة كوماتسو المرخّصة ونشرها كخدمة داخلية مسألة ترخيص أيضًا، لذلك لن نبني موصلًا يفكّ محتواها تلقائيًا.

**البديل المعتمد**: مسار «أرشفة» رسمي داخل النظام. الموظف يفتح CSS/LinkOne على جهاز ويندوز، يطبع/يصدّر كاتلوج المعدة PDF، ثم يرفعه عبر معالج الإدخال في التطبيق فيُؤرشف نهائيًا ويصبح متاحًا دون إنترنت للجميع. بالتوازي يبقى خط Komatsu العام الحالي (كتب + مخططات + أرقام قطع) هو المصدر الآلي، وهو يعطي بالضبط الرسم التفجيري وأرقام القطع المطلوبة.

## 2) المعدات التي ستُدخل (من ملف الإكسل — 46 صفًا)

تنظيف كامل: حذف كل البيانات التجريبية (12 مصنّعًا، الموديلات، الكاتلوج التجريبي، أنواع المعدات غير المستخدمة، المصادر التجريبية)، والإبقاء على **KOMATSU** فقط.

التصنيف المرن المعتمد (نوع المعدة ← عدد الأصناف):

- حرارة/بلدوزر: D50A-16، D50A-17، D60E-7، D65A-8، D65E-7، D75S-5، D85-18، D85-21، D155A-1، D155A-2، D155A-3، D275A-2
- جريدر: GD500R-1، GD511A، GD605A-2، GD661-A1، GD705-R2، GD705A-4
- غرافة (لودر): W90-2، W90-3، WA180-1، WA300-1، WA320-1، WA400-1، WA420-1، WA470-3
- بوكلين: PC220-7
- دكاكة: JV100A-1
- مولدات كهرباء: EG100-10052، EG125-2، EG220-1، EG2102-1، EG570B-3، EG5570B-3، EG630B-3، EG300B-3
- كمبريسر هواء: EC50Z-5، EC1052-1
- ملحقات وبومات: DRP050-24، DRP50-3، DRP060-4، DRP080-4، DRP150-1,2
- محركات/توابع: S6D105-1، SA6D140-1، SA6D125-1، NH-220-C1

الآلية: كل صف يصبح `machine_models` (اسم + رمز مُطبّع)، مع تسجيل الرمز المرتبط في `machine_aliases` (مثال: `DRP150-1,2` مرتبط بـ `D155-1`، و`SA6D140-1` مرتبط بـ `EG630B-3`)، وأنواع المعدات تُنشأ بأسماء عربية/إنجليزية. الملاحظة المهمة: الملف قائمة أصناف لا أرقام تسلسلية، لذا الأصول الفردية (`machine_assets`) تُضاف لاحقًا عند توفر الأرقام التسلسلية.

## 3) المراحل المعتمدة بالترتيب

- **المرحلة 0 — تصفير وتأسيس**: ترحيل يحذف البيانات التجريبية، يُبقي KOMATSU، ويُدخل أنواع المعدات والـ46 موديلًا ومرادفاتها.
- **المرحلة 1 — البحث برقم القطعة (الهدف الأساسي)**: توحيد فهرس القطع بضم `catalog_scheme_parts` إلى البحث، فيعطي إدخال رقم قطعة: القطعة واسمها → الكاتلوج والقسم/المخطط → الموديل، مع فهارس مناسبة وترتيب نتائج، ونفس الشيء لاسم القطعة ولاسم الموديل.
- **المرحلة 2 — صفحة الموديل + المخطط التفجيري**: من نتيجة البحث يفتح المخطط مباشرة، بجانبه جدول أرقام القطع، تظليل الصف/النقطة المطابقة، تكبير وتنقل بين المخططات.
- **المرحلة 3 — البحث في المصدر من داخل البرنامج + سحب كتب الـ46 معدة فقط**: شاشة «البحث في المصدر» داخل التطبيق (لا موقع خارجي): يكتب الموظف رقم قطعة أو موديلًا فيُنفّذ البحث على مصدر كوماتسو العام من الخادم، تظهر الكتب المطابقة بأسمائها، ثم يُسحب ويُؤرشف ما يخص الـ46 موديلًا فقط (المخططات + الصفحات + أرقام القطع + صور المخططات في التخزين الخاص) ليعمل دون إنترنت. الأسماء تُسحب أولًا ثم الكتب، مع شريط تقدّم واستئناف.
- **المرحلة 4 — معالج «إدخال معدة جديدة وكاتلوجاتها»**: مسار احترافي لإدخال السيديهات والملفات (اختيار/إنشاء الموديل ← بيانات المعدة والرقم التسلسلي ← رفع ملفات متعددة PDF بتحقق وتجزئة SHA-256 ← ربط تلقائي بالموديل ← أرشفة نهائية) مع سجل الإدخال ومنع التكرار.
- **المرحلة 5 — سجل مصدر ميجا/CSS**: تسجيل مخزن ميجا كمصدر «يدوي موثّق» داخل شاشة المصادر مع دليل خطوات الاستخراج من CSS ورفع الناتج، دون أي فك تلقائي لقاعدة EPC.
- **المرحلة 6 — بدائل القطع بنسبة تطابق**: تشغيل `suggest_part_alternates` الموجود مع عرض نسبة التطابق والجودة على صفحة القطعة.
- **المرحلة 7 — الأداء والواجهة الصناعية**: أعمدة محدّدة وتقسيم صفحات وتحميل مؤجل لإصلاح البطء، وتحسين الشكل ليماثل أنظمة كوماتسو/كاتربيلر.

## 4) تفاصيل تقنية موجزة

- الترحيل يبدأ بحذف الصفوف التابعة بالترتيب الصحيح (مخططات/قطع/كاتلوجات/موديلات/مصنّعين) داخل معاملة واحدة، ثم `INSERT` صريح لكل نوع معدة وموديل ومرادف — لا تعبئة من واجهة أو عند التحميل.
- توحيد البحث يعتمد فهرسًا نصيًا/ثلاثيًا على `catalog_scheme_parts.number`، `short_number`، `name`، وربط الصف بالمخطط والكاتلوج والموديل في استعلام واحد.
- تخزين صور المخططات في حاوية خاصة مع روابط موقّعة، وتسجيل كل ملف في `catalog_files` ليعمل مدير التنزيل والعمل دون إنترنت على بيانات حقيقية.
- لن يُحمّل أي ملف من ميجا داخل التطبيق أو بيئة البناء (4.2 جيجابايت للجزء الواحد).

## 5) ما أطلبه منك قبل التنفيذ

الموافقة على هذا الترتيب وعلى قرار ميجا (أرشفة يدوية من CSS بدلًا من موصل آلي). عند الموافقة أبدأ بالمرحلة 0 ثم المرحلة 1 وأتوقف لتقرير قبل المرحلة 2.
